## Measured zero, then closed

- **D, first run: 1 failure (16b only).** Case 16 as the QA plan wrote it
  slices from the clause result, which reaches the case node and `s = h()`
  through the branch's value and its scrutinee, never through a control parent.
  So case 16 did not protect control dependence. Closed in the same branch: case
  16 now also slices from `r = k()` alone (a node that reads nothing), whose
  slice is exactly itself, the case and `s = h()`; the D row above is the re-run.

## Rows that stayed green, and why

- Under G only case 24 reddens: case 23 and 25 assert regions that exist under
  either bound, and the region the mutation adds (`[a, b]`, two exits) is the
  shape only case 24 refuses. The red is a crash, not an assertion, because the
  mutated bound lets a two-exit list reach `region_output/1`; it is still the
  case-24 row, named.
- Case 17 stays green under D: the `with` body reads `a`, which the `with` node
  binds, so the node joins the slice by data dependence as well.
