## Measured zeros, and what was done about each

- **A8, an even integer read as a label: 0 failed.** `rem(label, 2) == 1` could not change a verdict, because windows open only at odd words, so the membership check already refuses an even integer. The guard was removed; row 11 of `classify` still holds it.
- **L7, a test's on_exit takes no label: 0 failed at first.** The runner takes the test's label from the test's last message, so the spec matters only when the test lost its own. A row was added ("on_exit after the test lost its label"), and L7 is now red.
- **S4, `--max-cases 1` not forced: 0 failed at first.** Nothing read the number. A fixture test now asserts `ExUnit.configuration()[:max_cases] == 1`, and S4 is now red.

## Rows that stayed green, and why

Most mutations leave most rows green on purpose: the Domain tables are about one rule each, and the fixture run reads the whole. G0 (crediting by the open window, QA's group sabotage) is the one that turns every "a real leak fails" row red.

## The unmeasured items the design named

- **`module_finished/2` word plus 2:** L1 (word left alone) and L2 (plus 1, so the word turns odd) are both red. L2 invalidates the whole fixture module, because the next test's window then opens at an even word and its entry message never comes.
- **The owner pid value:** `call_tracer_test.exs`, "the owner pid in a real Task spawn event", reads real spawn events for `start_child/3` (`noreply`), `start_child/5` temporary, `async_nolink` and `Task.async` (`reply`), and asserts the pid equals the test's own. O4 and O5 redden those rows.
- **Compile first combined with labels:** `coverage_integration_test.exs` runs the real command over a fixture project, with a server started in the test helper: the compile-time call is ambient, the server's handler is credited by label.
- **The chained clause:** does not exist. The measurement below built no gate.

## The review round's own killers

- **Row n3 (a linked process that dies with its test):** it used to assert absence, which held whatever the code did. It now calls a function inside the window and asserts credit with no leak, and A9 reddens it (C1 does not: a process with no owner is still credited by its label).
- **F2, the fresh VM:** found by a probe on the reviewer's question, before any fix: a fresh VM read a real version-2 map as `:undecodable` (`read: :error`), which would have made `run --coverage` exit 2 on a good map. The test boots a real child VM.
- **C3, what is queued behind `finish`:** the reviewer asked whether an off-heap queue can put `finish` ahead of a trace message. That was not settled against ERTS; the drain makes the answer not matter, and its test puts the messages behind `finish` by calling the callback directly.
